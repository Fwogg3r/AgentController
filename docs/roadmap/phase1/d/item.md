Owner design (2026-11-08). The owner passes a high-level idea. The SAME model that will do the work (no other model in the chain may be relied on) follows its instruction file to: (1) plan: break the idea into stages, each small enough for its own tier profile (files, context, output); (2) for each stage: plan briefly, then edit (aider architect/editor split, thinking on for planning, off or capped for edits); (3) verify: run the tests, fix, report; (4) record progress so a stage can be resumed from a fresh context. Every stage has to fit the lowest-end model in use, so the pipeline never assumes a smarter model will clean up.
Why: two idea-level runs on pmjc phase4/i part 2 failed the same way. Input was fine (40-51k of 64k), but Qwen spent its whole 16k output limit thinking in aider's single reply and wrote no edits. Exact-code briefs worked because they needed little thinking.

Preliminary goals and state (2026-11-08) are mirrored in the owner's private pmjc handoff. MVP target: `agentlocal` CLI that takes an idea, has the model write a stage plan (JSON, validated against the tier budget, approved by a human for low tiers), runs each stage as plan pass + edit pass with only that stage's files, tests, fixes up to N times, writes progress.json and stage summaries, and reports. First trial: pmjc phase4/i part 2.

Built 2026-11-08 (uncommitted, untested against a model): agentcontroller/local/ (config 4 layers, budget/preflight, streaming llm client with reasoning split and thinking budget, plan prompt + validator + 2 repair rounds, staged runner: spec -> aider edit -> scope guard -> gated tests -> fix with repeat-failure stop -> commit per stage, progress.json/resume, passthrough runner for top tiers, approvals: hook command / console / pending file), CLI `agentlocal probe|plan|run|resume|status`, examples/tiers.example.toml. Owner config: Z:/shared/agentcontroller/ (tiers.toml, LOCAL-AGENT.md). Only an import + config-load check ran. Next: unit tests for validate/budget/scope_guard; `agentlocal probe --model qwen-27b` (fills chars_per_token, checks /no_think); first trial on pmjc phase4/i part 2 from the owner's terminal (not from an auto-mode Claude session); replan check (prompt exists, not wired); agentdash view of runs (phase1/b reads .agentcontroller/runs/*/events.jsonl, thinking.txt).

Done 2026-11-10 (code-complete, unit-tested; not yet run against a real model, that is phase1/f): 48 tests pass (`uv run --with pytest pytest -q tests`; tests/test_local_config.py, test_local_plan.py, test_local_run.py, conftest.py; fake llm.chat, no aider). Bugs the tests and review found and fixed: a stage could depend on itself; plan paths could point outside the repo (`../`, absolute, `.git/`); non-list file fields were iterated as characters; acceptance commands with shell metacharacters passed the allowlist glob; the scope guard deleted the owner's pre-existing untracked files, missed files inside new untracked folders, did not restore deleted tracked files and left files aider had staged; `_check` kept literal quotes in arguments on Windows (now passes the string to CreateProcess) and inherited stdin; resume refused after a manual fix commit (now accepts a HEAD that descends from the last stage commit; `resume --mark-done N` marks hand-finished stages); resume ignored the run's tier; the thinking budget re-joined the whole reasoning on every chunk (quadratic). Replan wired: when a stage fails its acceptance check on every attempt (or the same failure twice), its changes go into a git stash and the model gets one replan of the remaining work (REPLAN prompt with the failure, criteria, finished stages and repo map), validated like the first plan (finished ids reserved, criteria covered by finished stages count) with the same repair rounds, behind the plan gate; `continue`, an invalid or a denied replan restores the stash and stops. At most one per run (`max_replans` 0|1, counted in progress.json before asking). Dashboard hooks: runs register in the machine registry (`registry.register_agent`, kind local, model/model_id/provider/tier/title/context_tokens/events/dir, `parent` from AGENTCONTROLLER_PARENT) and `ensure_dash()`; done/failed/stopped is written at exit (also on Ctrl-C and exceptions); registry errors never break a run. Every model call emits `call_start` (estimate) and `call` (measured) with `context_tokens`; thinking.txt/answer.txt are appended and closed per chunk with a header per call. Approvals: approvals/<id>.pending.json; answered by the repo hook, or by whichever comes first of the dashboard's approvals/<id>.json and a console answer (a stdin reader thread, so it works with a tty too); then the pending file is removed and <id>.json holds request + decision. Left: a real-model trial (phase1/f); summaries are still model-written, not AST-derived; a replanned run keeps the failed attempt in a git stash.
