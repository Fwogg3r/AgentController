# Decisions

## Local coding agents: tiered router + staged pipeline (2026-11-08)
Review: [docs/reviews/2026-11-08-local-agent-router-input.md](reviews/2026-11-08-local-agent-router-input.md) (proposal) and [...-opus.md](reviews/2026-11-08-local-agent-router-opus.md) (Opus critique). Roadmap phase1/d, e, f.

- **Options considered:** (a) aider alone with idea-level briefs; (b) aider architect mode (same model as architect and editor); (c) our own loop: plan and spec passes call the model directly, aider only applies edits with thinking off.
- **Decision: (c).** Evidence: exact-code briefs work with a 27B local model; idea-level briefs failed twice because thinking and edits compete for one capped reply. (b) keeps that problem and hides the reasoning. So the pipeline has the same model turn an idea into a validated stage plan, then each stage into an exact-code spec, then lets aider apply it.
- **Code does the arithmetic, the model the judgment:** per-file token costs computed by code and shown to the model; plans validated in code (files exist, file limits, token budget with preflight `input + max_output + reserve <= context`, acceptance command allowlisted, acyclic dependencies); at most 2 repair rounds, then a human.
- **Config in four layers:** model (facts: endpoint, context, max output, measured chars/token, thinking toggle, reasoning field), tier (policy: runner, file limits, thinking budgets per phase, autonomy, gates, fix attempts), repo (`[local]` in agentcontroller.toml: test command, acceptance allowlist, protected paths), environment (sandbox or not; effective autonomy = min(tier, environment)).
- **Top tiers are not slowed:** `runner = "passthrough"` hands the idea to one aider (or other) call with only event logging. Each run is scoped to the model running it.
- **Public vs personal:** the tool and an example tiers file are public; a user's tiers and instructions live wherever `AGENTCONTROLLER_TIERS` / `[local].tiers_path` points (the owner's: a private share). Paths in TOML as literal strings or forward slashes.
- **Safety:** the model never chooses shell commands; agentlocal runs the configured test command. Changed files outside the stage's list are reverted. Tests run model-written code, so low tiers gate test runs unless a sandbox is present. Don't launch it from an auto-mode Claude session; the owner launches it from a terminal.
- **Deferred:** outlines/context modes, sandbox provisioning and shell/full autonomy, Discord notifier (the command hook covers it), automatic tier choice, raw-completion budget forcing, multi-model chains.

## Unified dashboard across projects (2026-11-10)
Review: [docs/reviews/2026-11-10-unified-dash-opus.md](reviews/2026-11-10-unified-dash-opus.md) (Opus critique of the proposal). Spec: [docs/unified-dash.md](unified-dash.md). Roadmap phase1/b and phase2.

- **Discovery: registry + scan.** CLIs register agents in `~/.agentcontroller/agents/<id>.json` and projects in one file each (`projects/<hash>.json`, so concurrent CLIs can't lose updates); Claude Code sessions are found by scanning `~/.claude/projects` and mapping each dir to the `cwd` recorded in its transcripts (un-slugging is lossy), then to the main checkout (cached; deleted worktrees map by the `.claude/worktrees` convention). Scan-only misses worktree runs; registry-only misses Claude sessions. Registry records are pointers; state comes from the run's own files and the PID.
- **One code path.** `agentdash --all` is the default; `--project X` is the same server pinned to one project. Per-request config through a ContextVar instead of the module-global `CFG`.
- **Roadmap:** WebRoadmap owns the format; agentdash calls `roadmap --json list` and renders it itself (read-only, escaped markdown). Rejected: our own parser (drift), importing WebRoadmap (isolated uv tool env), iframing `roadmap serve` (N servers, second auth surface).
- **Always on:** a Task Scheduler logon task (run only when logged on, so Z: is mapped; `pythonw.exe`, no window; no time limit; restart on failure; IgnoreNew). `ensure_dash()` probes `/api/health` (mode "all"), runs the task first, spawns a hidden process only as a fallback. Never opens a browser. Rejected: a Windows service (session 0, no mapped drives), Startup shortcut (no restart).
- **pmjc:** over its HTTP API with a `jobs`-scope token kept server-side; never read its SQLite (locks stall its writers). `/api/approvals` needs pmjc's admin scope, so agentdash shows pmjc approvals only if the configured token has it, and the owner is advised not to give it admin; a read-only `observe` scope in pmjc is the follow-up. LM Studio status comes straight from each host's `/api/v0/models`, not pmjc's audited tool call.
- **Security:** POSTs need an `X-AC: 1` header besides the Host/Origin check; registry paths are served only under a `.agentcontroller` segment; no kill for registry-only PIDs (Windows reuses PIDs). A mandatory token was considered and rejected for localhost: agents run as the same user and could read it anyway; `--remote` keeps the token.
- **Deferred:** agents on other machines (SHEILA, laptop), a global daily budget, GPU arbitration between local agents, roadmap writes from the dashboard.

## agentdash internet access: Cloudflare Access + per-user levels (2026-11-10)
Review: [docs/reviews/2026-11-10-access-opus.md](reviews/2026-11-10-access-opus.md) (security review, Opus). Roadmap phase2/t.

- **A second listener, not a mode of the first.** The tunnel points at 127.0.0.1:`listen_port`; the same handler class runs there with an `access` flag, so both ports are served by one process (the logon task is unchanged). On it every request, including `/`, SSE and `/api/health`, needs a valid Access JWT regardless of `Host`. It is independent of `--remote`: the LAN token and cookie are ignored on that listener (and its page never sets the token cookie), so `--host 0.0.0.0 --remote` and the tunnel can run together. An earlier idea to make the two mutually exclusive was dropped.
- **JWT in the stdlib, no new dependency.** RS256 only (exact alg allowlist); key chosen by `kid` from the team JWKS (cached, an unknown kid refetches at most once per 60 s); the signature is checked by building the full expected EMSA-PKCS1-v1_5 encoding and comparing bytes with `pow(sig, e, n)` (the decrypted block is never parsed, which rules out Bleichenbacher-style padding flaws); signature length must equal the modulus length. Claims: `iss`, `aud` (string or list, any of the configured), `exp`/`nbf` with 60 s skew, `type == "app"` if present, `email` required (service tokens are rejected), lowercased.
- **Roles.** `super_admin` (from config, so the public repo holds no e-mail) is admin; everyone else comes from `grants.json` (written atomically by the sync on SHEILA, re-read on mtime change; missing or invalid fails closed). No grant: 403 "no access to agentdash".
- **Endpoint table, default-deny.** GETs are `view` except `/api/billed` (`operate`); POST inbox, local_approve, primary, launch, kill are `operate`; archive, worktree_delete, forget_project are `admin`; anything not in the table needs `admin`. Non-admins get scrubbed output (service URLs, error text, project paths, pmjc approval links); `/api/config` holds no key-file paths. `/api/me` returns `{email, level}` (`{local: true}` on the loopback port, `{lan: true}` with the token, both admin) and the page hides controls above the level; the server is the authority.
- **CSRF and audit.** POSTs on the access listener need JSON content type, `X-AC: 1` and an `Origin` exactly equal to `public_origin` (missing Origin is rejected). Every POST and every denied request goes to `access-audit.jsonl` (e-mail, level, method, path, query, body keys; text values over 200 chars are not logged).
- **Deferred:** rate limits and per-user budget caps for `operate` (roadmap phase2/u).
